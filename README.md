# ToolPick
Needs-based AI tool finder: 83 tools in 11 categories, prices copied from official pricing pages, a best-value pick and a free option.
Live: https://toolpick-ai.vercel.app

- `tools.py`: all data. Tool fields: name/url/pricing/price/free/about/why/affiliate (empty = official link). `PRICE_TABLE` holds the entry-plan monthly/annual price and cost per output; also `COMPARISONS`, `JOBS`, `SPONSOR_TIERS`, `CHECKED` date. Never invent prices; write "check site" when unverified.
- `build.py`: `python3 build.py` writes `public/` (index + finder, category pages, /tools/, /compare/, best-ai-tool-for-*, sponsor, newsletter, sitemap, robots, llms.txt, tools.json, og.png).
- `price_history.json` + `snapshot.py`: run `python3 snapshot.py` after each price re-check (after updating CHECKED) to log changes on /price-changes.html.
- `og_data.py`: base64 OG image, used when PIL is missing (e.g. in the Vercel build).
- `affiliates.md`, `growth.md`: monetization research and traffic plan.

## Deploy
Vercel project `toolpick-ai` runs `python3 build.py` itself (install `echo skip`, output `public`). Deploy with the Vercel MCP `create_deployment`, target production, `files` = build.py, tools.py, og_data.py, price_history.json (the MCP allows 4 `$file:` files per call) (inline via `$file:`). Always pass `projectSettings` {framework null, buildCommand `python3 build.py`, installCommand `echo skip`, outputDirectory `public`} plus `skipAutoDetectionConfirmation` 1: on 2026-10-19 a deploy without them skipped the build and served 404 until redeployed.

## AI price changes tracker (/price-changes.html, /price-changes.xml)
Generated automatically by build.py from `price_history.json` snapshots — no manual page edits.
1. Daily-ops edits a price in tools.py (verified on the official pricing page, with `checked` date).
2. Run `python3 snapshot.py YYYY-MM-DD` to add that day's snapshot to price_history.json.
3. Run `python3 build.py`. Any tool whose price text differs from the previous snapshot becomes a card
   (newest first), a "Recent price changes" box on its tool page, and an Atom feed entry. Tools that are
   new in a snapshot (no old value) are not shown as changes.
4. Optional: add a plain-English summary and tag in `PRICE_NOTES` in tools.py, keyed `"YYYY-MM-DD|Tool"`
   (tags: up, down, newplan, correction, currency, changed). Without a note the tag is guessed from the
   highest $ amount (up/down/changed) and a generic summary is used. Notes must only restate the
   documented old/new text. Snapshot artifacts go in `PRICE_SKIP` with a reason.

## Find my AI tool — help me choose 2.0 (/help-me-choose.html, v66, 2026-11-09)
`v66_picker.py` (embedded base64 in build.py, rewritten on every build — edit the module, then re-embed) rebuilds /help-me-choose.html after v65, replacing the v11 5-step wizard at the same URL. Four questions: (1) the job — all 35 `JOBS` grouped by category with a type-to-filter box, or "Anything in <category>"; (2) monthly budget (free/10/25/50/any, all seats), monthly or yearly billing, seats 1-50 (multiplies only per-seat prices, `_perseat`); (3) five facts as Don't mind / Nice to have / Must have: real free plan (`realfree`), no AI training without your OK (`PRIVACY`+`V57_PRIVACY` k in n/c), student deal (`STUDENT_OFFERS` for students; `STUDENT_SCHOOL_ONLY` = partly, `STUDENT_NONE` = no), refund window (`REFUNDS`+`V57_REFUNDS` k=w with a stated window; case by case / narrow = partly), cheaper yearly (numeric monthly vs per-month-billed-yearly, `V57_YEARLY` = monthly only); (4) what matters most (fit/cheap/privacy/free). Candidates: the job's 3 ranked picks plus tools whose main job (first `CAPS` tag) equals the #1 pick's or 2+ picks' main job; for a category, every tool in it. Budget and must-haves are hard filters (a fact we haven't checked never passes a must-have); paid-over-budget tools with a real free plan stay in as "free plan only". Ranking is visible points on every card (job fit 40/36/32/28, category Best Value 32 / others 24; nice-to-have +12 / partly +4 / no −6; free-plan-only −10; priority up to +20), ties by price then name. Each card has a checklist of what you asked for (yes/partly/no/not checked) with the official source link and checked date from the same `_row57` cells as the /compare/ pages. Also: "Left out and why", loosen-a-rule buttons with counts when <3 fit, compare-your-top-3 link into /compare-builder.html (want= carried), shareable URL `?job=voiceovers&budget=10&billing=y&seats=3&m_free=must&m_privacy=nice&pri=cheap` (old `?category=&budget=&billing=annual&free=required&annual=required` links still work). Pointer clicks on a job move to step 2; keyboard arrows never auto-advance. `link_v66` (run just before the sitemap) adds entry points on all 35 job pages (`p.v66`), the 11 category pages, the home finder and the /tools.html shortcuts.

## AI tool price history (/ai-price-history.html, v67, 2026-11-10)
`v67_history.py` (embedded base64 in build.py, rewritten on every build — edit the module, then run `python3 embed67.py` to re-embed) does three things:
1. **Classifies every recorded change** right after `CHANGES` is built: each `"YYYY-MM-DD|Tool"` diff gets a kind from `V67_KIND` in tools.py — real price moves (`raise`, `cut`, `cheaper` plan added, `top` higher plan added, `newplan`, `restructure` plans reorganized / not like-for-like, `rename` same price, `promo` intro offer changed) vs our listing updates (`detail` added detail, `correction`, `currency`). Optional `moves` `(plan, billing, before $, after $)` must only restate the documented old/new price text. Unlisted changes fall back to their `PRICE_NOTES` tag (up→raise, down→cut, newplan, correction, currency, else "Listing changed"). Diffs where only the `(checked …)` date changed and there is no note are dropped automatically. The kind's label is what /price-changes.html, the Atom feed, tool verdict rows and the watchlist show. **When daily ops records a new change, add a `V67_KIND` entry for it.**
2. **Builds /ai-price-history.html**: summary counts (raised / cut / plans / renamed / offers / no change found), a table of every documented price move (before → now, %, date, official page), a by-category table, and a card per tool (82) with its cheapest checked plan now, latest move, timeline of real moves, collapsed listing updates, tracked-since date and last-checked date with the official pricing link. Filters (JS, URL state): `?show=up|down|plans|names|offers|none&category=<id>&q=<text>&sort=recent|az|cheap|checked`; anchors `#t-<slug>`. FAQ + Dataset JSON-LD.
3. **Tool pages** get a "<Tool> price history" box (`#price-history`, `.tp67`) above the Visit button, and the trust panel's "Price history" line now counts real moves instead of raw text diffs. Links from /price-changes.html, /save-money.html and /guides.html.
