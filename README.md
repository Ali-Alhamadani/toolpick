# ToolPick
Needs-based AI tool finder: 83 tools in 11 categories, prices copied from official pricing pages, a best-value pick and a free option.
Live: https://toolpick-ai.vercel.app

- `tools.py`: all data. Tool fields: name/url/pricing/price/free/about/why/affiliate (empty = official link). `PRICE_TABLE` holds the entry-plan monthly/annual price and cost per output; also `COMPARISONS`, `JOBS`, `SPONSOR_TIERS`, `CHECKED` date. Never invent prices; write "check site" when unverified.
- `build.py`: `python3 build.py` writes `public/` (index + finder, category pages, /tools/, /compare/, best-ai-tool-for-*, sponsor, newsletter, sitemap, robots, llms.txt, tools.json, og.png).
- `price_history.json` + `snapshot.py`: run `python3 snapshot.py` after each price re-check (after updating CHECKED) to log changes on /price-changes.html.
- `og_data.py`: base64 OG image, used when PIL is missing (e.g. in the Vercel build).
- `affiliates.md`, `growth.md`: monetization research and traffic plan.

## Deploy
Vercel project `toolpick-ai` runs `python3 build.py` itself (install `echo skip`, output `public`). Deploy with the Vercel MCP `create_deployment`, target production, `files` = build.py, tools.py, og_data.py, price_history.json (the MCP allows 4 `$file:` files per call) (inline via `$file:`). Always pass `projectSettings` {framework null, buildCommand `python3 build.py`, installCommand `echo skip`, outputDirectory `public`} plus `skipAutoDetectionConfirmation` 1: on 2026-10-19 a deploy without them skipped the build and served 404 until redeployed.

## AI price changes tracker (/price-changes.html, /price-changes.xml)
Generated automatically by build.py from `price_history.json` snapshots — no manual page edits.
1. Daily-ops edits a price in tools.py (verified on the official pricing page, with `checked` date).
2. Run `python3 snapshot.py YYYY-MM-DD` to add that day's snapshot to price_history.json.
3. Run `python3 build.py`. Any tool whose price text differs from the previous snapshot becomes a card
   (newest first), a "Recent price changes" box on its tool page, and an Atom feed entry. Tools that are
   new in a snapshot (no old value) are not shown as changes.
4. Optional: add a plain-English summary and tag in `PRICE_NOTES` in tools.py, keyed `"YYYY-MM-DD|Tool"`
   (tags: up, down, newplan, correction, currency, changed). Without a note the tag is guessed from the
   highest $ amount (up/down/changed) and a generic summary is used. Notes must only restate the
   documented old/new text. Snapshot artifacts go in `PRICE_SKIP` with a reason.

## AI coding tool cost calculator (/ai-coding-cost.html, v60)
Generated by build.py from `CODECOST` in tools.py (Cursor, GitHub Copilot, Claude Code, Windsurf, Warp: individual + team plans, monthly/yearly per seat, flat team fees, seat limits, plan pick per usage level). Every price must be read on the official pricing page and `CODECOST_CHECKED` updated; build.py asserts each individual monthly price also appears in that tool's tools.py price text. Share params: `?seats=5&use=light|daily|heavy&bill=m|y&type=solo&plan=cursor:2`.

## Dealbreaker filters in the directory (/tools.html, v64, 2026-11-07)
Built by build.py from data that is already verified: `PRIVACY` (does it train on your data, PRIVACY_CHECKED), `REFUNDS` (REFUND_CHECKED), `STUDENT_OFFERS` (STUDENT_CHECKED) and the monthly-vs-yearly entry-plan prices (`_mym`, each tool's checked date). Tools missing from a list show "not checked" and are never put into that filter. Params: `?train=off|never|optout|biz`, `?refund=window|maybe`, `?student=yes|free`, `?yearly=save|20|40`, `?sort=yearly|checked`; combine with `category`, `job`, `free`, `price`, `view=table`. Each card lists the facts with links to the privacy, refund, student and monthly-or-yearly pages. Category pages and those four guides link to pre-filtered views (`p.v64`). Adding a tool to PRIVACY/REFUNDS/STUDENT_OFFERS updates the filters automatically (build asserts every listed tool is in the directory).

## Compare builder 2.0 (/compare-builder.html, v65, 2026-11-08)
`v65_compare.py` (embedded base64 in build.py, rewritten on every build — edit the module, then re-embed) rebuilds the compare builder after all data is loaded. For any 2-3 of the 82 tools it shows every fact already verified on official pages, side by side, using the same cells as the /compare/ pages' "Beyond the price" table (`_row57`: free plan, yearly billing, student deal, team plan, refunds + cancelling, data training, each with source + checked date), plus price (same-job, same-billing, comparable-tier rule) and usage limits (`USAGE`, never ranked). Rows get an "Ahead" mark by the v57 rules (ported to JS); price and team seats are never called across different main jobs. A "Which should you pick?" box tallies the rows the user marks as mattering (`?want=price,free,yearly,student,team,refund,privacy`) or all callable rows, and lists "Pick X if…" reasons. Share URL `?tools=a,b,c&want=…` (also accepts `?tool1=&tool2=&tool3=` from the no-JS form). Same-job "+ add" suggestions come from `samejob` (`al`). No-JS: a noscript list of all ready-made /compare/ pages. Every /compare/ page gets a `.v65` box linking into the builder (carries the page's `want=`) with add-a-third-tool links.
